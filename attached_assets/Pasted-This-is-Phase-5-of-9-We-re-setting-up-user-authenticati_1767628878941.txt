SECURITY REQUIREMENTS (Critical):

**Password Security:**
- Use bcrypt with minimum 10 salt rounds for hashing
- Never log or expose passwords in any error messages or console
- Never expose password hashes to the frontend

**Session/Cookie Security:**
- Cookies must be httpOnly (not accessible via JavaScript)
- Cookies must have secure flag in production (HTTPS only)
- Set sameSite to 'strict' or 'lax' to prevent CSRF attacks
- Regenerate session ID after login (prevents session fixation attacks)

**Database Security:**
- Use parameterized queries ONLY — never concatenate user input into SQL
- Drizzle ORM handles this, but double-check any raw queries

**API Security:**
- Rate limit auth endpoints: max 5 attempts per minute per IP
- Generic error messages only: "Invalid email or password"
- Never reveal whether an email exists in the system during login failures

**Input Validation:**
- Validate email format on server side
- Sanitize all user inputs
- Trim whitespace from email before storing
- The /api/auth/me endpoint should only return safe user data (id, email, name, role) — never the password hash
